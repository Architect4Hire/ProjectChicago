# Angular accessibility rules

- Meet WCAG 2.2 AA for new UI.
- Use semantic landmarks, headings in order, labels, descriptions, and native controls before ARIA.
- All interactive elements must be keyboard operable with visible focus.
- Do not communicate lifecycle stage, risk, success, warning, or error by color alone.
- Maintain accessible contrast for text, icons, borders, focus rings, and chart labels.
- Announce asynchronous errors and important success states appropriately.
- Respect reduced motion and browser zoom.
- Tables require captions or accessible names and header associations; responsive alternatives must preserve meaning.
- Components with dialogs, menus, steppers, or custom controls require focused accessibility tests.
